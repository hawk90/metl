- `expected<T, E>` and `expected<void, E>` are trivially destructible when `T` and `E` are, in every standard. They are then literal types in C++17 too, so a `constexpr` function can return one and `try_parse_*` runs at compile time in C++17. Each caller of a function returning such an `expected` drops the destructor's settled-state check, which could not fire for these types: half the code at a typical call site on Cortex-M. The type is still not trivially copyable, so it is passed and returned as before.
