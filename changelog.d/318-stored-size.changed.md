- **Breaking (ABI):** `fixed_vector`, `flat_map`, `flat_set`, `fixed_deque`, `ring_buffer`, and through them `fixed_queue`, `fixed_stack` and `fixed_priority_queue`, store their size, and the rings their head, in the narrowest unsigned type that makes the container smaller (#318 section 3). That type holds `Capacity`, and is never narrower than the element's alignment, which would only turn into padding. On Cortex-M, `fixed_vector<std::uint8_t, 8>` is 9 B instead of 12, `flat_map<std::uint8_t, std::uint8_t, 8>` 18 instead of 24, and `ring_buffer<std::uint8_t, 8>` 10 instead of 16. A container of `int` or wider elements has the same layout and code as before on a 32-bit target, because its counter stays `size_t`. On a 64-bit host it shrinks too. #318 measured this rule on CI's ARM GCC, with `fixed_string` narrowed too: 0 B of code net over a 42-function workload, with single functions moving by a few bytes. Locally (clang, `-Os`), every `int`-element function is the same instructions, and a `ring_buffer<std::uint8_t>` push is one instruction longer. `size()` and every interface still use `size_type`. `fixed_string` keeps its `size_t` for now (#697). Rebuild everything that shares one of these containers with code built against alpha.1.
